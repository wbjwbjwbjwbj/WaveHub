# 台站与传感器管理设计 v0.2

状态：第一阶段已接入前后端，采用现有 station / sensor 表。依据 `request.md`、`database-design.md`。
界面采用简洁深色风格，仅保留必要标题、字段、操作和错误反馈；不显示说明性小标题或演示提示。未修改表结构。

## 1. 本阶段目标

在页面中查询真实台站，为台站添加多个传感器，编辑后刷新仍能查询到完整数据。
传感器、波形采集设备是同一个实体，界面统一称“传感器”，字段说明中保留“传感器”含义。

本阶段范围：台站和传感器的查询、新增、编辑、启停用、受约束的删除，以及前后端联调。
批量导入导出作为下一阶段接入；地图、波形加载和算法计算在后续阶段接入。本版页面不放尚不可用的操作按钮。

## 2. 页面与操作流程

导航新增“台站管理”，路由 `/stations`，复用已有管理平台布局。左侧导航与顶部栏固定，内容区按导航宽度和顶栏高度留出位置。

页面采用上下两区：

- 上区为台站列表，支持编码 / 名称关键词、启用状态过滤；工具栏提供“新增台站”。
- 每行展示编码、名称、经度、纬度、高程、传感器总数、状态和操作。
- 点击“查看传感器”选中台站，下区展示该台站基本信息和传感器列表；切换台站会更新下区。
- 下区工具栏提供“新增传感器”和传感器关键词 / 状态过滤，每行提供编辑及删除。
- 台站或传感器的新增、编辑共用右侧编辑面板，桌面端作为独立侧栏；窄屏时使用固定的非遮罩编辑浮层。
- 左侧两张列表在独立容器内纵向排列，右侧编辑区不参与其行高计算。编辑面板按视口限高，字段独立滚动，标题及保存 / 取消操作保持可见。
- 名称、编码、经纬度为主字段；型号、采样率、扩展参数等在编辑面板中分组展示。

选择台站后将 ID 写入 `?stationId=<id>`，刷新可以恢复选择。列表页码、过滤值也可保存为查询参数；传感器分页参数使用独立名称，不能与台站分页混用。
分页后当前台站不可见时，下区可继续保留所选台站并显示其编码；筛选结果不自动选择另一个台站。
初次进入且无 stationId 时，默认选择第一页第一项；完全没有台站时显示“暂无台站”，引导创建。
无效或已删除的 stationId 显示明确提示并移除该选择，不默默切到其他台站。

### 编辑流程

1. 新增使用空表单；编辑先请求详情，成功后允许填写。传感器的所属台站由当前选择固定展示。
2. 保存前前端检查输入；提交期间禁用重复提交，后端重新执行全部校验。
3. 成功后关闭面板、刷新对应列表和传感器计数。新增台站自动选中新台站；编辑不改变当前选择。
4. 失败时保留表单内容，在对应字段或面板顶部显示错误。
5. 切换台站、关闭面板或离开页面时如有未保存改动，提示“放弃更改 / 继续编辑”。

## 3. 字段设计

### 台站

| 页面字段 | API 字段 / 数据库列 | 输入规则 |
| --- | --- | --- |
| 台站编码 | `code` | 必填，1–64 字符，字母 / 数字 / 下划线 / 连字符，全局唯一 |
| 台站名称 | `name` | 必填，去除首尾空格后 1–128 字符 |
| 经度（°） | `longitude` | 必填，-180 至 180，最多 7 位小数 |
| 纬度（°） | `latitude` | 必填，-90 至 90，最多 7 位小数 |
| 高程（m） | `elevationM` / `elevation_m` | 可空，最多 3 位小数，可为负值，遵守 NUMERIC(12,3) 范围 |
| 启用状态 | `enabled` | 默认启用，API 使用 boolean，数据库映射 1 / 0 |
| 说明 | `description` | 可空，本版界面和接口限制为 2000 字符 |

`id`、创建时间、修改时间由后端维护；ID 对外为字符串。列表增加只读派生字段 `sensorCount`，统计所有传感器，不新增数据库列。
编码去除首尾空格、保留大小写，本版按数据库现有唯一约束区分大小写。是否统一转大写留待实际编码规范确定。

### 传感器

| 页面字段 | API 字段 / 数据库列 | 输入规则 |
| --- | --- | --- |
| 所属台站 | `stationId` / `station_id` | 从请求路径确定，创建后本版不支持迁站 |
| 传感器编码 | `code` | 必填，格式与台站编码相同，同台站内唯一 |
| 传感器名称 | `name` | 必填，1–128 字符 |
| 经度、纬度、高程 | 与台站同名字段 | 使用传感器实际位置，与台站中心分别维护 |
| 类型 | `sensorType` / `sensor_type` | 可空，最多 64 字符，先使用文本输入，不编造类型字典 |
| 型号 | `model` | 可空，最多 128 字符 |
| 序列号 | `serialNumber` / `serial_number` | 可空，最多 128 字符，不预设全局唯一 |
| 标称采样率（Hz） | `nominalSampleRateHz` / `nominal_sample_rate_hz` | 可空；填写时必须大于 0，最多 8 位小数，遵守 NUMERIC(20,8) 范围 |
| 扩展参数 | `parameters` / `parameters_json` | 高级项，JSON 对象，默认 `{}`，本版最多 16 KiB UTF-8 |
| 启用状态、说明 | 同台站 | 可停用，说明最多 2000 字符 |

本版参数结构版本由后端固定为 1，用户不手工填写。JSON 文本框明确标为高级项，可折叠；它用于尚未确定的设备参数，后续可替换成业务表单。
采样率未知时保持空值，不能填写 0 代表未知。空值在列表中显示“未配置”，不显示成 0。
可以提供“复制台站坐标”快捷动作，但必须由用户主动点击；不把默认复制的坐标伪装为已测量传感器位置。
坐标暂按 WGS84，以输入精度保存；表格可以显示较少小数，详情和表单保留原值，不能将展示舍入值回写数据库。

## 4. 规则和边界

### 启停用

- 编辑面板设置启用状态，保存时一并更新，不额外提供独立的状态接口。
- 停用台站不修改传感器自身的 enabled；后续计算的有效传感器需同时满足台站和传感器均启用。
- 停用不删除或隐藏历史数据，页面始终可通过状态筛选查看。

### 删除

- 单条删除先显示对象名称并要求确认；第一版不提供批量删除。
- 台站下存在任何传感器时拒绝删除，返回传感器数量，提示“请先处理关联传感器，或停用台站”。
- 传感器被 `waveform_trace` 或 `analysis_task_input` 引用时拒绝删除，提示停用；不自动清除历史波形映射或任务记录。
- 后端在事务中检查关联；数据库外键提供并发情况下的最终保护。引用冲突统一返回 409，不将数据库原始错误直接显示给用户。
- 删除最后一页的最后一条记录后，退回上一页再查询。删除所选台站后清除 stationId，下区恢复未选中状态。

### 加载与失败

- 列表首次加载显示骨架；网络失败保留过滤条件并提供重试，不展示伪造的成功数据。
- 正常空结果显示“没有符合条件的台站 / 传感器”，和加载失败分别处理。
- 当前版本采用后保存覆盖先保存的编辑策略；保存动作只修改 DTO 允许编辑的字段，不能覆盖创建时间或技术参数版本等只读字段。
- 暂不增加 version 列或乐观锁。多人同时编辑、历史追踪如有实际需求再设计迁移。

## 5. 接口草案

所有响应复用 `{code, message, data}`。分页数据为 `{records, total, page, size}`，page 从 1 开始，size 默认 20、最多 200；默认按 createdAt 降序、id 降序稳定排序。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/stations` | 分页查询台站：keyword、enabled、page、size |
| POST | `/api/stations` | 新增台站 |
| GET | `/api/stations/{stationId}` | 查询台站详情及传感器总数 |
| PUT | `/api/stations/{stationId}` | 更新台站全部可编辑字段 |
| DELETE | `/api/stations/{stationId}` | 删除无关联传感器的台站 |
| GET | `/api/stations/{stationId}/sensors` | 分页查询所属传感器：keyword、enabled、page、size |
| POST | `/api/stations/{stationId}/sensors` | 在指定台站下新增传感器 |
| GET | `/api/stations/{stationId}/sensors/{sensorId}` | 查询传感器详情 |
| PUT | `/api/stations/{stationId}/sensors/{sensorId}` | 更新传感器全部可编辑字段 |
| DELETE | `/api/stations/{stationId}/sensors/{sensorId}` | 删除未被波形或任务引用的传感器 |

keyword 去除首尾空格、最多 128 字符。台站匹配 code / name，传感器匹配 code / name / serialNumber；关键词中的 SQL 通配符作为普通字符处理，查询必须参数绑定。
PUT 表示全部可编辑字段的替换：必填字段缺失报错，可选字段缺失或显式 null 均清空；前端每次提交完整表单。`parameters` 省略时按空对象处理。
所属台站只取路径参数；传感器接口必须校验 sensorId 确实属于该 stationId，不能只按 sensorId 直接修改或删除。
JSON 参数以对象传输，后端序列化为 TEXT；响应将其解析回对象，不让前端处理双重转义字符串。
新增成功使用 HTTP 201，并返回所创建对象；更新成功 HTTP 200 返回更新对象，删除成功 HTTP 200 返回 data=null。

HTTP 与业务错误：

| HTTP | 业务 code 示例 | 用途 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 字段错误，data 可包含 fieldErrors 字段到提示的映射 |
| 401 | `UNAUTHORIZED` | 尚未认证或 Session 过期 |
| 403 | `FORBIDDEN` | 无权限或 CSRF 令牌无效 |
| 404 | `STATION_NOT_FOUND`、`SENSOR_NOT_FOUND` | 对象不存在或传感器不属于指定台站 |
| 409 | `STATION_CODE_EXISTS`、`SENSOR_CODE_EXISTS` | 编码唯一性冲突，包括并发写入冲突 |
| 409 | `STATION_HAS_SENSORS`、`SENSOR_IN_USE` | 引用关系阻止删除 |
| 503 | `DATABASE_UNAVAILABLE` | 金仓不可用或当前非 kingbase 模式 |

## 6. 现有框架的接入安排

- 前端新增 station / sensor 类型、请求函数、管理视图和编辑组件；查询状态以页面局部状态为主，不把表单全部塞入全局 Pinia。
- 后端新增 `modules/station`，按 controller、service、mapper、entity、dto 分层，复用现有 ApiResponse。
- station / sensor 使用现有表及 MyBatis-Plus；实体字段与 API DTO 分离，Service 负责唯一性、归属、引用及事务规则。
- 对台站列表的传感器数量使用聚合查询或批量统计，避免每个台站单独发起一次查询。
- 业务数据服务仅在 kingbase 模式连接真实库；独立模式显示明确不可用状态，不使用示例列表代替数据库结果。
- 现有 SecurityConfig 对业务接口要求认证，但 UserDetailsService 为空。数据库连接成功并不意味着管理接口已经可以访问。
- 已采用环境变量提供的单一开发账号、Session 登录及退出，保留 CSRF；不新增用户 / 角色表，不在代码中写默认密码。账号配置为 `WAVEHUB_ADMIN_USERNAME`、`WAVEHUB_ADMIN_PASSWORD`。
- 配套认证若采用上述建议，需要补充登录入口、当前会话查询和登录失效处理；业务接口不能通过全局 permitAll 或关闭 CSRF 来绕过现有约定。

## 7. 验收清单与实现顺序

1. 确定原型访问方式，打通认证和带 CSRF 的写请求。
2. 完成台站查询与新增、编辑，页面读取真实金仓记录。
3. 完成传感器查询与新增、编辑，验证编码作用域和台站归属。
4. 完成启停用、删除确认、引用冲突和异常状态。
5. 在专用开发库验证：创建一个台站、添加至少 3 个传感器、修改后刷新、停用后恢复、重复编码失败、有引用删除失败、无引用删除成功。
6. 验证超范围坐标、非正采样率、非法 JSON、跨台站 ID、未登录请求和无 CSRF 写请求均被拒绝。

业务页面通过真实接口读写金仓。统一验证命令及启动方式见 `running-and-testing.md`；集成测试写入的数据在事务结束后回滚并检查清理结果。
